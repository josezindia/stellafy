# Architecture and stack

| Layer | Tools |
|---|---|
| Presentation | HTML, Jinja2, Tailwind CSS (or plain CSS initially), HTMX, JavaScript |
| Application | Python, Flask, Blueprints, session |
| Data | SQLite, SQL, Flask-SQLAlchemy, Flask-Migrate |
| Analytics | Pandas, Chart.js |
| Workflow | uv, Git, GitHub, Pytest, VS Code, Figma |
| Deployment | PythonAnywhere or Render, subject to hosting plan limits |

Browser → Flask routes → services → SQLAlchemy → SQLite. Flask renders Jinja templates; HTMX can replace a small HTML fragment rather than reload the page. Keep money calculations separate from routes. Use integer cents or Decimal; choose and document rounding, and calculate retained revenue as commission minus contribution.

## Target structure (grow into it)
```
stellafy/
├── app/
│   ├── __init__.py       # create_app factory
│   ├── extensions.py    # database and migrations
│   ├── models.py        # SQLAlchemy models
│   ├── routes/          # main, products, cart, checkout, dashboard
│   ├── services/        # impact and analytics
│   ├── static/          # css, js, images
│   └── templates/       # base, index, products, cart, checkout, dashboard, partials
├── instance/            # SQLite database, ignored
├── migrations/          # generated when models exist
├── scripts/             # seed data
├── tests/
├── .env                 # ignored secrets
├── .env.example
├── pyproject.toml
├── uv.lock              # generated by uv sync
├── config.py
└── run.py
```

A factory creates and configures the app; a Blueprint groups routes; an ORM maps Python objects to tables; migrations track schema changes; a partial is a small HTML snippet; a lockfile records specific dependency versions. Authentication is optional, not required for a demo.
